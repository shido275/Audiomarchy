# Audiomarchy

**The producer's omakase — a music-production workstation built as an overlay on
[Omarchy](https://omarchy.org).**

Not "Omarchy with a DAW installed." A machine that behaves like a studio
computer: a real-time audio engine that does not drop your interface, buffers
you can change from the launcher, a session focus mode, a virtual cable, and
Windows plugins that open like native ones.

It installs on top of a stock Omarchy system. Nothing Omarchy owns is touched,
and `omarchy update` leaves it intact.

## What it is

- **An overlay.** `./install.sh` on a working Omarchy install. No ISO, no fork.
- **Menu-native.** Everything lands in the launcher you already use:
  **Music**, and **Trigger → Music** for the actions.
- **One app, one script.** Every package is a leaf under
  `install/apps/<category>/`, installing exactly that app.
- **Studio plumbing, not just packages.** Realtime privileges, PipeWire tuning,
  WirePlumber device keep-awake, USB power pinning, XWayland plugin rules,
  a virtual loopback, and a doctor that explains what is wrong.
- **Reversible.** Config lives in `~/.config`; every overwritten file is backed
  up; no system config is modified except installing packages and adding your
  user to the `realtime` group.

## What it is not

- Not a fork of Omarchy, and not a custom ISO.
- Not a replacement for your distro — it adds to an Omarchy install.
- It never writes to `/usr/share/omarchy/` or `~/.local/share/omarchy/`.
  Those are package-owned and get wiped on update.
- It does not ship a signed binary repository (yet): packages come from the
  Arch repos and the AUR.

## Requirements

- A working Omarchy install (the installer refuses to run without `omarchy`).
- Arch Linux, x86_64.
- PipeWire (Omarchy ships it).
- Several gigabytes of disk for a DAW plus plugins. The curated core is
  deliberately smaller than `--pack all`.

## Install

```bash
git clone https://github.com/<you>/audiomarchy.git
cd audiomarchy
./install.sh
```

It asks for your password once, up front, then runs unattended. Every run is
logged to `~/.local/state/audiomarchy/latest.log`.

```bash
./install.sh --dry-run      # show every change, touch nothing
./install.sh --list-packs   # what is available, with counts
./install.sh --pack all     # everything in the tree
./install.sh --pack core,effects-all
```

Packs replace the default selection rather than adding to it. `core` is the
curated studio; `<category>-all` is one category in full.

| Category | Core | Total |
|---|---|---|
| daws | 2 | 3 |
| instruments | 4 | 7 |
| effects | 4 | 7 |
| routing | 3 | 4 |
| mastering | 2 | 2 |
| live | 0 | 2 |
| notation | 1 | 1 |
| tools | 4 | 4 |

## What you get

### The Music menu

Under **SUPER + SPACE → Music**:

- **DAWs** — REAPER, Ardour, Bitwig (if installed)
- **Instruments** — Surge XT, Cardinal, Hydrogen, SFizz, Vital, FluidSynth, DrumGizmo
- **Effects** — LSP, Calf, Dragonfly, x42, ZamPlugins, EasyEffects, Guitarix
- **Routing** — Carla, qpwgraph, Helvum, JACK tools
- **Mastering** — Audacity, Sonic Visualiser
- **Live & DJ** — Mixxx, Qtractor
- **Notation** — MuseScore
- **Tools** — yabridgectl, Wine configuration, realtime check

Entries are generated by asking pacman what each package installed. A package
that is not installed produces no menu row; the menu never points at a guessed
binary.

### Windows plugins, iLok, Waves and Native Instruments

A dedicated Wine prefix (`~/.wine-audiomarchy`), a yabridge build matched to
your Wine version, and one command to run any Windows plugin installer:

```bash
audiomarchy plugins install ~/Downloads/PluginSetup.exe
audiomarchy plugins vendor ilok     # also: waves, ni
audiomarchy plugins doctor
```

Honest limits: iLok has no Linux support (software/Cloud licenses sometimes
work, a USB dongle does not), Native Access 2 does not run under Wine (legacy
1.x does), and Waves v14 is far more reliable than v15. Details and
troubleshooting: [docs/windows-plugins.md](docs/windows-plugins.md).

The tricky part is the version pairing: Arch ships Wine 11, which upstream
yabridge 5.1.1 cannot host plugins on, so the installer switches to the
Wine 10+ build from the AUR instead of leaving you with a bridge that cannot
load a single plugin.

### The audio engine

- **Realtime privileges** — `realtime-privileges` plus your user in the
  `realtime` group, so PipeWire and DAWs can ask for RT scheduling and lock
  memory.
- **48 kHz, 256-frame default** — about 5.3 ms per period, with
  `min-quantum = 32` so a DAW can still ask for more.
- **Devices never suspend** — a WirePlumber drop-in keeps ALSA nodes awake and
  adds headroom, so the first note after a pause is not clipped and the
  interface does not vanish between takes.
- **USB power pinning** — `audiomarchy device usb-power on` stops the kernel
  from autosuspending USB audio-class interfaces.
- **Loopback** — `Audiomarchy Loopback` (sink) and `Audiomarchy Loopback Mic`
  (monitor remap): a persistent virtual cable. Record what you hear, or route
  an app somewhere silently.

### Latency profiles

| Profile | Quantum | Buffer at 48 kHz | Use |
|---|---|---|---|
| `safe` | 1024 | 21.3 ms | big sessions, soft synths, mixing |
| `balanced` | 256 | 5.3 ms | default |
| `low` | 128 | 2.7 ms | tracking |
| `ultra` | 64 | 1.3 ms | low-latency monitoring, fast machine |

```bash
audiomarchy audio latency low   # applies live and persists
audiomarchy audio status
audiomarchy audio reset
```

The profile is written to PipeWire's config **and** forced into the running
graph, so you do not restart the audio server to change buffer size.

### Session mode

**Trigger → Music → Start Session Mode** (or `audiomarchy session start`):

- power profile → performance
- notifications → do not disturb (Audiomarchy's own notification still shows)
- idle, suspend and lid handling inhibited
- buffer → 128 frames
- optional `--offline` turns Wi-Fi off

`audiomarchy session stop` restores every setting it changed, one by one, from
the state it recorded. If something was already set that way, it stays.

### Windows plugins, without the pain

`yabridge` + `wine-staging` are in the core. Put VST2/VST3 files where
yabridgectl expects them, then:

```bash
audiomarchy plugins scan
```

That creates the standard folders (`~/.vst`, `~/.vst3`, `~/.lv2`, `~/.clap`),
runs `yabridgectl sync`, and prints the paths to point your DAW's scanner at.

The Hyprland rules make bridged plugin editors float instead of being tiled,
and force XWayland to 1:1 scaling so their UI and mouse coordinates stay
correct.

### The `audiomarchy` command

```bash
audiomarchy audio status
audiomarchy audio latency [safe|balanced|low|ultra]
audiomarchy device list
audiomarchy device loopback on|off
audiomarchy device usb-power on|off
audiomarchy session start ["Name"] [--offline]
audiomarchy session stop|status
audiomarchy plugins scan|status|dirs
audiomarchy project new "Track name" | list | open
audiomarchy doctor
audiomarchy menu | refresh | update
```

### Studio folders

`~/Music/Audiomarchy/` with `Projects`, `Renders`, `Samples`, `Recordings`,
`Presets`. `audiomarchy project new "Name"` scaffolds a project with `Stems`,
`Renders`, `Recordings` and a `session.md` for notes.

## Where things go

| What | Path |
|---|---|
| CLI | `/usr/local/bin/audiomarchy` |
| Engine profile | `~/.config/audiomarchy/profile` |
| PipeWire drop-in | `~/.config/pipewire/pipewire.conf.d/90-audiomarchy.conf` |
| WirePlumber drop-in | `~/.config/wireplumber/wireplumber.conf.d/90-audiomarchy.conf` |
| Loopback | `~/.config/pipewire/pipewire-pulse.conf.d/90-audiomarchy-loopback.conf` |
| Studio window rules | `~/.config/hypr/audiomarchy.conf` |
| Menu entries | `~/.config/omarchy/extensions/omarchy-menu.jsonc` |
| Post-update hook | `~/.config/omarchy/hooks/post-update.d/audiomarchy-refresh.hook` |
| Logs and state | `~/.local/state/audiomarchy/` |
| Repo copy | `~/.local/share/audiomarchy/repo` |

Menu entries are merged between BEGIN/END markers, so reruns replace rather
than duplicate, and the merged file is validated before it is written. Omarchy
silently drops a menu it cannot parse, so a bad merge is never left in place.

## Updating

```bash
omarchy update     # also runs the Audiomarchy hook: menu + rules refreshed
audiomarchy update # pull the repo copy and rerun the installer
```

## Adding an app

Drop a leaf at `install/apps/<category>/<package>.sh`:

```bash
#!/bin/bash
# pack: core
source "$AUDIOMARCHY_INSTALL/helpers/pkg.sh"
au_pkg_add sonic-visualiser
```

Leaves are discovered with `find`; there is no manifest. Add a row to
`install/music/menu.tsv` for a launcher entry. Syntax-check before committing:

```bash
bash -n install.sh $(find install -name '*.sh') bin/audiomarchy
```

## Honest limitations

- **True aggregate devices** (multiple interfaces clocked as one) are not
  implemented. PipeWire can combine outputs, but interfaces without a shared
  word clock will drift. The loopback covers the common "route audio between
  apps" case; use qpwgraph for custom graphs.
- **Windows plugins are a bridge, not a port.** Some copy protection, iLok and
  kernel-level anti-cheat do not work under Wine. Check
  [yabridge's compatibility notes](https://github.com/robbert-vdh/yabridge).
- **No AU support.** That is a macOS-only plugin format. Native CLAP, LV2,
  VST3 and VST2 are the targets here.
- **Realtime group changes need a re-login.** The installer adds you to
  `realtime`; the limits only apply to new sessions. `audiomarchy doctor`
  tells you when that is still pending.
- **A realtime kernel is optional.** Most interfaces are fine on the stock
  Arch kernel; the doctor reports which one you are on rather than installing
  one behind your back.
